# AgentNodify

Qt 6 / QtNodesによるチャット型エージェントのワークフローエディタです。
仕様: [`spec/spec.md`](spec/spec.md)。Windows 11 / Qt 6.12.0 / MSVC 2022でビルド・自動テスト済み。

## ビルドと起動

必要なもの: CMake 3.24以上、Visual Studio 2022の「C++によるデスクトップ開発」、Qt 6.5以上（MSVC x64版）。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
.\build\Release\AgentNodify.exe
```

Qtの場所が異なる場合は `-QtPath C:/Qt/<version>/msvc2022_64` を指定します。
初回構成時に固定バージョン・SHA-256検証付きで依存ライブラリを取得します。
ネットワーク制限下ではCMakeの `FETCHCONTENT_SOURCE_DIR_JSON`、
`FETCHCONTENT_SOURCE_DIR_JSON_VALIDATOR`、`FETCHCONTENT_SOURCE_DIR_QTNODES` に展開済みソースを指定できます。

手動でビルドする場合:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=C:/Qt/6.12.0/msvc2022_64
cmake --build build --config Release --parallel 8
$env:PATH = "C:/Qt/6.12.0/msvc2022_64/bin;$env:PATH"
ctest --test-dir build -C Release --output-on-failure
C:/Qt/6.12.0/msvc2022_64/bin/windeployqt.exe build/Release/AgentNodify.exe --no-translations --no-compiler-runtime
```

配布先にはVisual C++ 2022ランタイムも必要です。

## 使い方

1. 左下の `＋` でフローを追加、または「ファイル → 開く」で `examples/*.flow.json` を開きます。
2. 左ペインのボタンでノードを追加します。丸い出力ポートから入力ポートへドラッグして接続します。
   フロー一覧の右クリックで名前変更・一覧から削除、`＋`で新規作成・既存フロー追加を選べます。
   QtNodes自体の制約により、同一ノードへの直接ドラッグ接続はこのダイアログを使用します。
3. ノード図形内のフォームで、名前・エージェント・モデル・入力数・分岐条件を編集します。
   プロンプト／スキーマの複数行プレビューをクリックすると、右の複数行エディタが開きます。
   編集内容はノード内に即時反映され、プレビューは折り返しも含めて1〜8行に自動伸縮します。
   ノードやノード追加ボタンの上にカーソルを置くと、機能説明のツールチップが表示されます。
   ペイン境界はドラッグできます。キャンバスはホイールでズームできます。
   編集・作業画面とも、背景をクリックしてSpaceを押すとフロー全体を画面に収めます。ノードや入力欄にフォーカスがある場合は発動しません。
   始端・終端は初めから各1個配置されているため、追加ボタンはありません。
4. F7で検証、Ctrl+Sで保存。「名前を付けて保存」で任意の場所へJSONとして保存できます。
5. 「ツール → CLI設定」で各エージェントの実行ファイルを設定します。
   認証・プロバイダ・権限は各CLIで事前設定してください。
6. 左端の角丸正方形ボタンでフローを切り替え、同じ枠内の`＋`でフローを追加できます。
   始端・終端は黄色の1行ノードで表示し、ユーザー向けのノード連番は表示しません。
7. 「プロジェクト作業」で作業ディレクトリを追加し、実行します。
   ノードをクリックすると状態・進行ログ・次段への出力を確認できます。
   右ペインは「実行履歴」「進行状況 / CLIログ」「次段への出力」の縦3分割です。
   実行履歴はノードの実行1回ごとに日時付きで残り、ループの各回を選んで確認できます（フロー実行単位のグループ分けはしません）。
   履歴を選ぶとその回を表示し、「最新を追従」でライブ表示に戻れます。履歴はアプリ内に保存され、再起動後も復元します。
   保存先の`AppDataLocation/history/`にはCLI出力を含む平文JSONがあるため、共有・配布時には注意してください。
   履歴は選択したノードだけを対象に日時・実行番号・エージェントを表示し、未選択時は空になります。実行番号・エージェント・作業ディレクトリは内部データに保存します。
   発言はMarkdown、JSONはツリーで表示します。最終応答は「次段への出力」だけに表示します。JSON内の長い文字列は500文字、配列は8要素までを表示します。
   ツール呼び出しは名前と状態を表示し、入力・出力はそれぞれ折りたたみから展開できます。ファイル操作は名前とアクセス種別で確認できます。
   未対応イベントは簡易表示に残します。CLIが明示しないシェル内部のファイルアクセスは推測せず、履歴の元データも変更しません。

### スクリプトノード

「＋ スクリプト」から、言語（Python／JavaScript）、ファイルパス、実行ディレクトリを設定できます。
パス欄の「参照…」ボタンから、スクリプトファイルと実行ディレクトリをGUIで選択できます（手入力も可能です）。
システムのPython／Node.jsが必要です。相対パスはプロジェクト基準で、実行ディレクトリを空にするとスクリプトのある場所を使います。

- 標準入力: 前段データをUTF-8のJSONで渡します（文字列もJSON文字列）。Pythonは`json.load(sys.stdin)`、Node.jsは`JSON.parse(fs.readFileSync(0, "utf8"))`で受け取れます。
- 標準出力: JSONならその値を、その他は文字列として次段へ渡します。進捗メッセージは標準エラーへ出してください。
- サンプル: `examples/script.flow.json`（Python→JavaScript）。このリポジトリのルートをプロジェクトに指定して実行してください。
- スクリプトはユーザー権限で実行され、エージェントCLIの権限設定は適用されません。信頼できるファイルだけを実行してください。

### シェル実行ノード

「＋ シェル実行」から、コマンド内容と実行ディレクトリを設定できます。コマンドはプレビューをクリックして右ペインで複数行編集でき、`${stdout}`などで前段の値を使えます。

- シェルはWindowsでPowerShell、その他では`/bin/sh`です。
- 実行ディレクトリの省略時・相対パスの基準は、**フローの保存先ディレクトリ**です。「参照…」からの選択も可能です。
- 出力は`{"exit_code": 0, "stdout": "...", "stderr": "..."}`です。終了コードが0以外でも結果を後段へ渡すため、分岐ノードで判断できます。
- サンプル：`examples/shell.flow.json`。
- 入力は自動クォートされず、シェル構文として解釈されます。信頼できるコマンド・入力だけを使用してください。エージェントCLIの権限制限は適用されません。

### エージェントのモデル選択

モデル候補は各エージェントのCLIから**自動取得**します。起動時・エージェント切替時・選択欄を開く際に
非同期で取得し、結果を10分間キャッシュします。ノード内の`↻`、または「ツール → モデル一覧を更新」で再取得できます。
取得中・取得失敗の状態もモデル欄に表示します。失敗時は前回の候補があれば保持し、固定の推測候補には置き換えません。
モデル選択欄は取得した候補から選ぶ形式です。手入力や「CLI既定」はなく、実行前にモデルを選択します。
既存のフローのモデルIDは一覧更新で変更せず、一覧外のIDも「現在の設定」として残します。
実モデルのテストには仕様で許可されたGPT-6.0-Luna / Haiku 5.5のみを選んでください。

取得元はCodexの`app-server` → `model/list`、Claude Codeの制御プロトコル初期化応答、OpenCodeの`models`です。
プロンプトや推論リクエストは送らず、認証情報のコピーや自動ログインはしません。
Claude Codeの一覧取得プロセスでは通常のユーザーフックとMCPの起動を抑制します（管理ポリシーは引き続き適用）。
各CLI設定とアプリの起動時作業ディレクトリの設定に基づく候補であり、個別プロジェクトでの実行権限・課金可否までは保証しません。
実行ファイルの場所は「ツール → CLI設定」で変更できます。WindowsでのOpenCodeの初期値は`opencode-cli`です。
旧初期値の`opencode`はWindowsで自動移行します（手動指定のパスは変更しません）。

ノードの「思考量」は未指定ならCLI・モデルの既定値です。モデルが対応する値を選んでください。
ファイル作成が権限で拒否される場合は、右ペインのCLIログ・最終出力を確認します。
書き込みは標準で許可し、Codexでは`workspace-write`、Claude Codeでは`acceptEdits`を指定します。
CLI設定に書き込み許可の切り替えはありません。既存の拒否ルールは維持し、ClaudeのモードはOSサンドボックスではありません。
OpenCodeは既存の権限設定に従います。CLIの正常終了だけではファイル作成成功とは判断しないでください。

## タスクトレイ常駐

- ウィンドウ右上の閉じるボタンでは終了せず、トレイに常駐してフロー実行を継続します。
- トレイアイコンをクリック、または右クリック →「表示」でウィンドウを戻せます。
- アプリの終了はトレイの右クリック →「終了」（または「ファイル → 終了」）です。呼び出し先を含む実行中のフローがある場合は警告し、確認後に全実行を中止して保存・終了します。
- トレイが使えない環境ではウィンドウを隠さず案内を表示します。「ファイル → 終了」で終了してください。

## 実行ルール

### 別フローとの連携

登録済みフローを選択し、プロジェクトパスを指定する3種類のノードがあります。パスには`${name}`等の前段出力を利用でき、相対パスは実行元プロジェクト基準です。フォルダ参照UIはありません。

- **AgentNodify プロジェクト作成**: ディレクトリを用意して登録。`{"result":"success","path":"..."}`または`{"result":"failed","reason":"project_already_exists"}`等を返します。同じフロー・パスの重複は失敗です。
- **AgentNodify フロー実行**: 登録済みの対象を非同期に開始。`result`は`started`／`already`／`failed`です。
- **AgentNodify フロー終了**: 対象の終了を待ち、終端へ渡された値をそのまま返します。完了済みなら直ちに返します。未開始・失敗・中止・循環待機はノードエラーです。

通常は「プロジェクト作成 → フロー実行 → フロー終了」の順に接続します。既に登録済みの場合は、作成結果を分岐で処理するか実行ノードから始めてください。作成の失敗ID一覧と待機仕様は`spec/spec.md`に記載しています。

呼び出し先の実行と履歴はプロジェクトごとに独立します。呼び出し元が終わっても呼び出し先は継続し、「停止」は全実行を止めます。完了結果の待機用キャッシュは再起動で消えます（保存した履歴は残ります）。

### 基本ルール

- 始端・終端は各1つ。始端の出力は `{}`。終端には前段の値をそのまま渡します。
- 通常ノードの入力ポートは1つ、出力ポートからは任意本数にファンアウトできます。
  同じ入力ポートに複数の辺を接続でき、入口とループの戻り辺や分岐の合流を受けられます。
  ANDは入力ポート数を指定できます。
- `${a}`、`${hoge.foo}`、`${foobar[1]}` を前段の値で置換します。
  ANDの配列には `${[0].name}` の形式でアクセスできます。再帰的な再置換はしません。
- スキーマ上の未定義変数は実行前エラー。任意プロパティの欠落や配列範囲外は実行時エラー。
  スキーマのパス検査は明示的な `properties` / `items` とローカル `$ref` が対象です。
  `allOf` 等の合成スキーマからの変数推論は未対応です（応答そのものの検証には対応）。
- JSON Schema **Draft 7**を使用し、メタスキーマによる定義の検証と応答データの検証を行います。
  `format` は注釈扱い、外部URLの `$ref` 読み込みは行いません。
- ANDは入力の到着順ではなく、**ポート番号順**に配列を作ります。
  各入力のFIFOから1件ずつ消費して発火し、消費済みの状態をリセットして次の全入力を待ちます。
  先着した複数イベントを上書きせず、次の待ち合わせ用として保持します。
- 分岐は上から最初に一致した条件、なければelseの出力に伝播します。
  文字列はそのまま、数値・真偽値・オブジェクト等はJSON表現と比較します。
- 非選択出力は発火せず、ANDの入力完了にも数えません。if/elseの合流には通常ノードの
  同じ入力ポートを使ってください。未実行ノードはフロー完了時にスキップ表示になります。
  **旧版の非選択入力をnullとしてANDへ渡す動作は廃止**しました。
- **ループを許可**します。前段からイベントを受けるたびに通常ノードは再実行します。
  同じエージェントノード内はFIFOで直列実行し、別ノードは並列実行できます。
  ループ内でも全ての前段スキーマについて変数を検証し、循環を理由に検証を省略しません。
- 発火可能なイベントと実行中プロセスがなく、終端へ到達済みなら完了です。
  ANDに片側だけの入力が残り、進めるノードがない場合は入力待ちエラーになります。
  初回の始端発火は1回だけです。停止条件のないループは「停止」で中止してください。
  エージェントを含まない高速ループも定期的にGUIへ制御を戻すため、停止操作が可能です。
- 未接続入力、未接続の分岐出力、到達不能ノード、終端へ到達できない経路はエラーです。
- ノードのポート数変更時は、そのノードの辺を解除します。番号の意味が変わる誤接続を防ぎます。
- エージェントは並列実行可能。フロー全体では同時に1プロジェクトを実行します。
  エラー時は全体を停止。実行中のフロー編集・プロジェクト切替はできません。

## CLI連携と制約

| エージェント | 呼び出し | JSON出力 |
|---|---|---|
| Codex | `codex exec --json`（stdinでプロンプト） | `--output-schema`、最終応答ファイル |
| Claude Code | `claude -p --verbose --output-format stream-json`（stdin） | `--json-schema`、`structured_output` |
| OpenCode V2 | `opencode run --format json` | **プロンプトでJSON Schemaを指示し、受信後に検証** |

OpenCode CLIには公開ドキュメント上、ネイティブな出力スキーマ指定がありません。
したがってOpenCodeのみ生成時のスキーマ強制は保証せず、不一致の応答は失敗にします。
CLIのバージョン差や各プロバイダのスキーマ制約により、CLI側で拒否される場合もログへ表示します。
既存セッションの再利用はせず、各エージェントノードを独立タスクとして起動します。

プロンプトをシェルのコマンド文字列へ展開せず、QProcessの引数／stdinで渡します。
Windowsの `.cmd` / `.bat` ラッパーは非対応です。ネイティブ `.exe` を指定してください。
Windowsでは起動後にPATHが変更された場合も、現在のユーザー／マシンのレジストリPATHから
実行ファイルを再検索します。GUI版OpenCodeではなく、`run --format json`を受け付けるCLIを指定してください。
Codex／Claudeの書き込み許可以外に、全操作の自動承認やsandbox無効化フラグは追加しません。その他の権限は各CLIで設定します。
通常実行の自動タイムアウトはありません。対話待ちなどで進まない場合は「停止」を使ってください。
停止は起動したCLIプロセスを強制終了します。CLIが別途起動した独立プロセスや
OpenCodeのバックグラウンドサービス上の処理までの停止は保証しません。
機密を含むプロジェクトを実行する前に、CLIのデータ送信先・権限を確認してください。

## 保存

- フローファイル: バージョン付きJSON、アトミック書き込み。
- 既定の保存先: QtのAppDataLocation配下の `flows/`。
- プロジェクト一覧・CLIパス: 同じ場所の `workspace.json`。
- 終了時、変更済みの全フローを保存します。外部から開いたファイルも保存対象です。
- 実行ログ／結果はメモリ内のみで、再起動またはフロー編集により消えます。
  フローファイル自体には含めません。

## 構成 / 依存ライブラリ

- `src/flow.*`: データモデル・JSON保存・グラフ／スキーマ／変数検証
- `src/runner.*`: 非同期実行・分岐と合流・CLIプロセス／プロトコル
- `src/history.*`: ノード1実行ごとの履歴のアトミック保存・再起動時の復元
- `src/progress.*` / `src/progressview.*`: CLIイベントの表示用解釈、Markdown・JSONツリー、ツール・ファイルアクセスのタイムライン
- `src/modelcatalog.*`: 推論を行わないモデル一覧の非同期取得・キャッシュ
- `src/cli.*`: 共通のCLI実行ファイルの解決
- `src/graph.*`: QtNodesのAbstractGraphModel実装
- `src/window.*`: Qt Widgetsの編集画面・プロジェクト画面
- QtNodes 3.0.12（BSD-3-Clause）
- nlohmann/json 3.11.3（MIT）
- nlohmann/json-schema-validator 2.3.0（MIT）
- Qt（利用するディストリビューションのライセンスに従ってください）
